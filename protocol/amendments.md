# Changes since design v3 of 22 Nov 2026 - folded into protocol v4, frozen 24 Nov 2026

Rows 1-10 come from the probes of 22 Nov 2026. Rows 11-28 come from the dress rehearsal of 23 Nov 2026 (`rehearsal/R/rehearsal_report.md`) and the dry runs of 24 Nov, and were accepted by the principal on 23-24 Nov. They change mechanics only; no forecasting wording changes.

They are part of the frozen protocol and are folded into `design.md` v4; where a row is more specific than the design text, the row governs. No scored forecast existed when any of them was made; the only forecasts that existed were the rehearsal's and the dry runs' unscored ones.

| # | Section | Change | Why |
|---|---|---|---|
| 1 | 3 | The parser ignores a FORECAST line that only repeats the format template with unfilled placeholders, and ignores quotation marks around a line. The prompts give the format inside a sentence, with letters in place of numbers. | Deliberate restates its question at the start of every call. With the old wording that restatement would have counted as a second, conflicting forecast line and voided every run. |
| 2 | 9 | Twin claim rule completed: if the starting claim is itself a move of any size, the twin claim is "no change". | The old wording covered only a 25 bp starting claim. |
| 3 | 1, 13 | Venue rule texts are recorded by address, capture time and fingerprint, not republished. Raw venue responses are kept privately with their fingerprints; the public ledger carries the extracted quote tables. | The rule texts belong to the venues. A fingerprint lets anyone check the text without the pilot copying it. |
| 4 | 1 | January identifiers added (see `venues.md`). | Found by the probe. |
| 5 | 6 | Adapter rules confirmed (see `venues.md`). | Probe. |
| 6 | 4, 5 | Documents and venue responses are saved by a download triggered inside the browser page, with a fingerprint computed in the page and checked against the saved file. No model re-types any page. | In the probe a small model failed to copy 2,000 characters of an official page exactly, twice. A test download matched its in-page fingerprint byte for byte. |
| 7 | 6 | One-sided books: a missing bid counts as 0 and a missing ask as 100, flagged. Only when both are missing is the last trade used, flagged; with no last trade either, the venue is invalid for that capture. | Under the old wording Kalshi would have been invalid at every capture, because its far-from-the-money contracts routinely have no bid. |
| 8 | 2 | Each Fable call writes its answer to a file and replies only that it is done. The forecasting wording is unchanged. | The runner never re-types an answer and never needs to read one before the commitment. |
| 9 | 5, 9 | The twin Deliberate run starts after the scored run and may end after the deadline. It gets its own commitment when it ends. | It is a diagnostic and is never scored; two full runs may not fit one window. |
| 10 | 4 | Speeches and testimony are taken from the Board's yearly listing pages. Pages are saved whole, menus included. | The combined landing page shows only recent items. Saving the whole page removes a judgment about where a document starts. |
| 11 | 4, 5 | Documents and venue responses are saved through the principal's Chrome (Claude in Chrome), set once to save without asking and to allow automatic downloads from the five sites. The save snippet stops the page's own click handlers. Every reported file is checked on disk within 60 seconds and re-saved once at once if missing. | In the rehearsal the built-in browser held every download for a manual save, which cost about 3.5 hours, and 23 of 24 T2 quote files never reached disk. The Chrome route was tested on 24 Nov with no clicks on all five sites. |
| 12 | 2, 11 | Memory ("Generate memory from chats") is paused for the whole pilot, and every checkpoint opens with a channel check that must report CHANNEL CLEAN before any model call. | The rehearsal channel check found that every call, the model arms included, was shown the principal's memory list, which named this experiment and both venues (no prices). |
| 13 | 5 | Checkpoints run unattended as scheduled sessions. The principal sets up the machine once and adjudicates afterwards; the runner never waits for a person. Replaces "The lab's principal starts every checkpoint and is reachable until T3. No unattended runs in the pilot." | Decision of the principal, 24 Nov. Every runner decision the rehearsal needed a person for is now fixed in the run sheet or logged. |
| 14 | 2, 14 | The Fable calls run on an agent type with only file read and write tools, and each call's tool record is kept for the compliance scan. | In the rehearsal the Fable calls ran on a type with web search, web fetch and memory tools, and no tool record was kept, so the scan could not be done. |
| 15 | 2, 3 | The Deliberate arm becomes "Deliberate plus elicitation step" (section 3): one frozen call copies the forecast stated in Deliberate's final call onto a line of its own, or writes NO_FORECAST. The parser reads only that line. The final call's text is committed beside it. | Both rehearsal runs put the forecast inside a longer line, so the parser found no line. Section 3 provided for this case. |
| 16 | 9 | The twin and repeat Deliberate runs are dropped from scored checkpoints. The scored run is the only Deliberate run. | Each run takes 1.2-1.5 hours; three in sequence do not fit the window. Plan usage per checkpoint drops to about 9 points of the all-models meter. |
| 17 | 13 | Publication goes through the GitHub connector, with `pack.md` split into parts of at most 60 KB that must concatenate to `pack.sha256`. `pack.sha256` is published. Each file's git blob hash is checked after the push. | Git push is blocked from the session and the principal's machine; the connector cannot carry a 400 KB file. The rehearsal rebuild needed `pack.sha256`, which was not published. |
| 18 | 10 | The Deliberate conductor builds every read-set file a dispatch names before dispatching, from a written checklist, and puts the call-record schema in every dispatch. A call record the harness blocks is logged as missing; the conductor never writes it for the operator. | Rehearsal: two read-sets were missing at P6, two operators opened other calls' records to learn the schema, and one record write was blocked. |
| 19 | 5 | A T2 quote file missing on arrival is a failed capture at once and is re-saved within minutes, with its new time logged. | Rehearsal: the missing T2 files were found hours later. |
| 20 | 5 | Preflight before T0: frozen-fingerprint check, tests, channel check, tool check of the Fable arm's agent type, one test save. A failure fails the checkpoint, logged. | Makes an unattended run stop cleanly instead of running on a bad setup. |
| 21 | 4 | Verified files are moved out of `~/Downloads` into the checkpoint folder. | Keeps Downloads from filling with pilot files and keeps each checkpoint's files in one place. |
| 22 | 5 | The runner sends the principal a short notice at the end of each checkpoint: done or failed, arms valid, commitment address. No prices. | Unattended runs need an outcome signal. |
| 23 | 2 | The restricted agent type is delivered as a plugin (`fomc-pilot`) installed on the principal's account and named `fomc-pilot:pilot-forecaster`. | Dry run DR (24 Nov): scheduled sessions do not load agent types from the repository; plugin agent types do load. |
| 24 | 4, 5 | A saved file's fingerprint is its sha256 computed on disk after arrival, with its byte count checked against the in-page count. The in-page sha256 is checked too where the browser tool returns it. | Dry run DR: the Chrome tool redacts long hex strings in its output, so the in-page fingerprint does not reach the runner. |
| 25 | 11 | CHANNEL CLEAN means: no venue name, no price or probability tied to the decision, and nothing about this experiment, in anything a model call is shown before its prompt. Names and descriptions of the principal's installed tools and skills do not count. | Dry run DR: with memory off, the only hits were skill names (Deliberate, CDL). Accepted by the principal, 24 Nov. |
| 26 | 11 | The channel check runs on the model arms' agent type with model Sonnet, not Fable, and asks four yes/no questions (`prompts.md`) instead of asking the call to list its pre-prompt context. The context a call is shown before its prompt depends on the agent type, not the model. | Dry runs of 24 Nov: Anthropic's safeguards stopped every request to list the pre-prompt context (Fable twice, Sonnet three times). The yes/no wording returned CHANNEL CLEAN three times, twice in scheduled runs, with no safeguard stop. |
| 27 | 4, 5 | Moving verified files out of `~/Downloads` may need delete permission there; the runner requests it once, for `~/Downloads` only, and otherwise copies the files, leaves the originals and logs it. | Dry run of 24 Nov 10:38 UTC: the move needed delete permission in Downloads. |
| 28 | 2, 10 | A model call that writes its answer file but replies with more than DONE has not failed. The answer file governs; the extra reply is logged without numbers. | Dry runs of 24 Nov: one Fable call repeated its forecast line in its reply after writing a valid file. |
